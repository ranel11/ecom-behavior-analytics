# 🛒 eCommerce Clickstream Analytics System (SQLite & SQL)

## 📌 Описание проекта
Проект посвящен построению продуктовой аналитики на основе лога кликстрима (clickstream data) крупного интернет-магазина за ноябрь 2019 года. 

Основная цель проекта — преобразовать сырые неотсортированные данные объемного лога в оптимизированную реляционную базу данных SQLite, спроектировать витрины данных (Data Marts) и провести продуктовый анализ (воронки конверсий, Retention, LTV и поведение пользователей).

---

## 🛠 Технологический стек
* **Язык:** Python 3.x
* **СУБД:** SQLite3
* **Библиотеки:** Pandas, time, sqlite3
* **Оптимизация:** B-Tree индексирование, пакетная загрузка (Chunking)

## 📊 Описание сырой таблицы (`events`)
Сырые данные представляют собой файл CSV объемом **67+ миллионов строк**, содержащий информацию о действиях пользователей на сайте.

### Структура колонок:
| Колонка | Тип данных | Описание |
| :--- | :--- | :--- |
| `event_time` | DATETIME | Дата и время события (UTC) |
| `event_type` | TEXT | Тип действия: `view` (просмотр), `cart` (в корзину), `purchase` (покупка) |
| `product_id` | INT | Уникальный ID товара |
| `category_id` | BIGINT | Уникальный ID категории |
| `category_code` | TEXT | Текстовая категория (например, `electronics.smartphone`) |
| `brand` | TEXT | Бренд товара |
| `price` | REAL | Цена товара в $ |
| `user_id` | INT | Уникальный ID пользователя |
| `user_session` | TEXT | Уникальный UUID сессии |

## 🏛 Структура витрин данных (Data Marts Layer)

### 1. Витрина сессий (`dim_sessions`)
Агрегированная таблица уровня отдельных пользовательских сессий. Служит основой для расчета сессионных воронок конверсии и оценки длительности визитов.

| Колонка | Тип данных | Описание |
| :--- | :--- | :--- |
| `user_session` | TEXT | Уникальный UUID сессии |
| `user_id` | INT | Уникальный ID пользователя |
| `start_session` | DATETIME | Время начала сессии (первое событие) |
| `end_session` | DATETIME | Время окончания сессии (последнее событие) |
| `session_duration_sec` | INT | Длительность сессии в секундах |
| `views_count` | INT | Количество просмотров товаров в сессии |
| `cart_count` | INT | Количество добавлений в корзину в сессии |
| `purchase_count` | INT | Количество совершенных покупок в сессии |
| `has_view` | INT (0/1) | Флаг наличия хотя бы одного просмотра в сессии |
| `has_cart` | INT (0/1) | Флаг наличия хотя бы одного добавления в корзину |
| `has_purchase` | INT (0/1) | Флаг наличия хотя бы одной покупки в сессии |
| `total_revenue` | REAL | Суммарная выручка, сгенерированная за сессию ($) |

### 2. Витрина пользователей (`dim_users`)
Агрегированная витрина клиентского профиля. Позволяет оценивать жизненный цикл пользователя (Lifetime), показатели вовлеченности, RFM-сегментацию и LTV.

| Колонка | Тип данных | Описание |
| :--- | :--- | :--- |
| `user_id` | INT | Уникальный ID пользователя |
| `lifetime_days` | INT | Время между первой и последней сессией пользователя (в днях) |
| `recency_days` | INT | Количество дней с последней активности до конца периода базы |
| `total_sessions` | INT | Общее количество сессий пользователя |
| `total_views` | INT | Суммарное количество просмотров товаров |
| `total_cart` | INT | Суммарное количество добавлений в корзину |
| `total_purchases` | INT | Суммарное количество совершенных покупок |
| `ltv_revenue` | REAL | Накопленная выручка с пользователя (LTV) |
| `is_buyer` | INT (0/1) | Бинарный маркер платящего пользователя |

### 3. Товарная витрина (`dim_products`)
Агрегированная справочная витрина по всем товарам каталога. Используется для ABC-анализа, анализа воронки конверсии конкретных товаров и ценового позиционирования.

| Колонка | Тип данных | Описание |
| :--- | :--- | :--- |
| `product_id` | INT | Уникальный ID товара |
| `category_id` | BIGINT | Идентификатор категории товара |
| `brand` | TEXT | Бренд товара (с обработкой пропусков `Unknown`) |
| `unique_users` | INT | Количество уникальных пользователей, взаимодействовавших с товаром |
| `views_product` | INT | Общее количество просмотров товара |
| `cart_product` | INT | Общее количество добавлений товара в корзину |
| `purchase_product` | INT | Общее количество покупок товара |
| `avg_price` | REAL | Средняя фактическая цена продажи товара ($) |
| `min_price` | REAL | Минимальная зафиксированная цена товара ($) |
| `max_price` | REAL | Максимальная зафиксированная цена товара ($) |
| `product_revenue` | REAL | Суммарная выручка, принесенная товаром ($) |

### 4. Материализованная витрина интервалов покупок (`user_purchases_timeline`)
Специализированная аналитическая витрина, очищенная от дублей транзакций в рамках одной секунды/чека. Содержит точную хронологию покупок каждого пользователя с привязкой к его первому заходу на сайт (`first_view`).

| Колонка | Тип данных | Описание |
| :--- | :--- | :--- |
| `user_id` | INT | Уникальный ID пользователя |
| `now_time` | DATETIME | Время текущей покупки |
| `prev_purchase` | DATETIME | Время предыдущей покупки (или `first_view` для 1-й покупки) |
| `diff_minutes` | REAL | Интервал в минутах от предыдущего события (`first_view` / пред. покупка) |
| `purchase_order` | INT | Порядковый номер уникальной транзакции пользователя (1, 2, 3...) |

### 5. Витрина путей и Марковских переходов (`06_purchase_paths_matrix`)
Специализированная материализованная витрина для анализа поведенческих цепочек (Behavioral Path Analysis). Содержит агрегированные вероятности переходов между временными интервалами покупок с глубиной истории в 5 шагов (`prev_1` ... `prev_5`). Построена на базе `user_purchases_timeline` с использованием строгого `LEFT JOIN` для исключения ошибок несовпадения родителей.

| Колонка | Тип данных | Описание |
| :--- | :--- | :--- |
| `purchase_order` | INT | Порядковый номер текущей покупки (1, 2, 3...) |
| `time_int` | TEXT | Текущий интервал между покупками (`24h`, `1-3d`, `4-7d`, `8d`) |
| `prev_1` | TEXT | Интервал предыдущей покупки ($N-1$) |
| `prev_2` ... `prev_5` | TEXT | Интервалы глубокой истории ($N-2$ ... $N-5$) |
| `current_count` | INT | Количество пользователей в данном специфическом пути |
| `parent_count` | INT | Объем базовой когорты родительского шага ($N-1$) |
| `percent` | REAL | Конверсия удержания/перехода в процентном выражении (%) |

### 🔄 Блок 3. Марковский анализ путей покупок и «Петли привычки» (Habit Loops)

В рамках третьего блока аналитики была исследована марковская модель переходов пользователей между покупками на основе таблицы `mart_06_purchase_paths_matrix`.

#### 1. «Точка невозврата» (Aha-moment) и динамика удержания в ритме `24h`
Было проанализировано поведение пользователей, совершающих регулярные покупки с интервалом до 24 часов (`24h`).

| Покупка (`purchase_order`) | База когорты (`parent_count`) | Сохранили ритм `24h` | Retention % | Поведенческий статус |
| :--- | :--- | :--- | :--- | :--- |
| **№3** | 17,583 | 6,500 | **36.97%** | Вход в воронку привычки |
| **№4** | 12,731 | 6,093 | **47.86%** | **🔥 AHA-MOMENT (+10.89%)** |
| **№5** | 7,987 | 4,402 | **55.11%** | Закрепление паттерна |
| **№7** | 3,989 | 2,557 | **64.10%** | Необратимый Retention |
| **№10** | 1,956 | 1,398 | **71.47%** | Ядро супер-пользователей |
| **№30+** | 213 | 185 | **86.85%+** | Абсолютная лояльность |

**Ключевые продуктовые выводы:**
1. **Aha-Moment на 4-й покупке:** На 4-й покупке удержание совершает самый резкий скачок (**+10.89%**), преодолевая порог в **47.86%**. Именно 4-я покупка подряд в ритме `24h` является точкой невозврата, превращающей пользователя в постоянного клиента.
2. **Формирование супер-пользователей:** К 10-й покупке удержание в цикле превышает **71%**, а после 30-й покупки достигает **85–96%**. Отток среди активной группы становится близким к нулю.

#### 2. Подтверждение Марковского принципа (Memoryless Property)
Сравнение траекторий клиентов на 5-й покупке показало, что глубина истории далее 2–3 шагов практически не влияет на текущее поведение:
* Траектория `24h` $\rightarrow$ `24h` $\rightarrow$ `24h` $\rightarrow$ **`24h`** даст вероятность следующей покупки **57.01%**.
* Траектория `8d` $\rightarrow$ `24h` $\rightarrow$ `24h` $\rightarrow$ **`24h`** даст вероятность следующей покупки **57.42%**.

> **Вывод:** Прошлое не имеет значения, если сформирован текущий контекст. Для прогнозирования следующего заказа достаточно учитывать последние 2–3 действия пользователя.

#### 3. Структура «Срыва» привычки на 4-й покупке
Из 6,500 пользователей, имевших идеальную историю из 3 покупок `24h`, на 4-м шаге сбиваются с ритма **51.69%**.

* **48.31%** — Сохраняют ритм `24h`.
* **35.06%** — **Полный отток (Churn).** Уходят из сервиса безвозвратно, не сделав 4-й заказ.
* **6.78%** — Переходят в замедленный режим `1-3d`.
* **5.28%** — Выпадают в критический интервал `8d+`.
* **4.57%** — Переходят в режим `4-7d`.

**Стратегические рекомендации для бизнеса:**
1. **Focus Area:** Направить все стимулирующие коммуникации (Push, e-mail) на пользователей между 2-й и 4-й покупками. Доведение клиента до 4-й покупки окупает затраты за счет многократного роста LTV.
2. **Ограничение скидок:** Полностью отключить маржинальные скидки для клиентов с 10+ покупками — их органическое удержание превышает 70–80%.
3. **Критическое окно реактивации:** Отправлять триггерные уведомления строго на **25–28 часах** после покупки. Если клиент не вернулся в первые 24 часа, шанс его полного оттока возрастает до **35%**.
